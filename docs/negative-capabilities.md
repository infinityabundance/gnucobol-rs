# Negative-capability registry

> _Generated document (TRUST.4.DOCS). Machine authority: `reports/claim-ladder.json` + `reports/casefiles/`. Legacy source preserved losslessly under `research/legacyreports/docs/negative-capabilities.md`._

A serious reviewer trusts a project that says **"no"** as precisely as it says **"yes."** This registry states, as loudly as each sealed capability, exactly what gnucobol-rs does **not** claim — *what* is rejected, *where*, with *which guard*, *why*, and *how* a surface earns its way off this list. It is the negative half of the same trust surface that `COBOL-PARITY.md` covers positively; read the two together, because a non-claim here is only meaningful against the sealed subset there.

**Accuracy rule (binding).** Nothing sealed may appear below as a non-claim. A surface with a court ID and a green receipt is a *capability*, not a gap; listing it here would be a lie of omission in the other direction. Every entry below has been cross-checked against the 160-court claim ladder so that no sealed surface is mis-stated as a gap. The four non-claim **types** are kept in distinct sections, each with its own departure semantics: §3a deliberate non-goals, §3b fail-closed-and-shrinking forms, §4 true oracle boundaries, §5 genuinely-open work.

## 1. Doctrine — fail closed

gnucobol-rs is an independently written (per the author's committed from-scratch claim — strict clean-room provenance is not independently verifiable from the committed record, see [methodology](docs/methodology/parser-front-end-provenance.md)) COBOL reader + interpreter over a 1:1 Rust port of the GnuCOBOL 3.2 `libcob` runtime. **No `cobc` is invoked and no `libcob` is linked.** Correctness is judged solely by stdout bytes being byte-identical to the admitted `cobc` 3.2 oracle (and, where applicable, a second pinned 3.1.2 differential oracle).

The single governing rule:

> **Fail closed. An unsupported surface is explicit evidence, never inferred behaviour.**

- Anything outside the sweep-verified subset returns a typed `RunError::{Unsupported, UndefinedName, Runtime, SizeError}` (`frontend.rs:69-93`) — never a guess. Through the host driver it prints `cobrun: <reason>` and exits `2`. There are **183 `RunError::Unsupported` emit sites** in `frontend.rs`; every one is a deliberate "no," not a latent bug.
- **A reviewer can confirm any row** by feeding the construct to `cobrun` and watching it refuse on stderr — never see it silently produce output.
- Refusal under `#![forbid(unsafe_code)]` is itself a positive property where the C oracle relies on undefined behaviour (e.g. an out-of-bounds subscript adjacent read): the port refuses or returns a category default rather than reproducing the UB.

A surface leaves this registry by exactly one of the routes in §6 — never by drift or an implied "probably works."

## 2. The compile axis — what we DO claim (context for the non-claims)

Context first, so the non-claims below are read against a real, verified positive surface.

**We claim** a clean-room COBOL front-end (`GNURUST.FRONTEND.1`) that **parses and executes** a sweep-verified subset of COBOL on the ported `libcob` runtime, producing stdout **byte-identical to `cobc -x`**.

- **Receipt of record:** `reports/receipts/GNURUST.FRONTEND.1/receipt.md` — current **`PASS=93 FAIL=0`**, with **84** of those also differential-matched against a second pinned oracle (GnuCOBOL **3.1.2**).
- **Depth.** A seven-phase pipeline: host driver → copybook expansion → conditional-compilation preprocessor (`>>DEFINE/IF/ELSE/END-IF`, `>>TURN … CHECKING`) → case-fold + lexer → SPECIAL-NAMES/ENVIRONMENT scan (CURRENCY, `DECIMAL-POINT IS COMMA`, UPSI switches, EBCDIC collation) → program split + multi-pass data-layout build → execution.
- **Breadth.** 58 statements run end-to-end (DISPLAY, MOVE, the full arithmetic family, COMPUTE with standard precedence and exact-scale accumulation, IF / PERFORM / EVALUATE / GO TO incl. DEPENDING, SEARCH (serial), OPEN/READ/WRITE/REWRITE/DELETE/START sequential+relative, SORT/MERGE single-key, STRING/UNSTRING/INSPECT, JSON/XML GENERATE+PARSE, **contained** CALL, …); **94 of 110** intrinsics run from the front-end; all standard data-description clauses build and execute (PICTURE, USAGE, VALUE, OCCURS, REDEFINES, RENAMES, level 88/77/66, ODO, INDEXED BY, SIGN, SYNCHRONIZED, JUSTIFIED, BLANK WHEN ZERO, EXTERNAL, GLOBAL).
- **Runtime substrate.** The underlying runtime is 100% sealed — all 13 admitted `libcob` files ported 1:1, and **all 110 intrinsics ported 1:1 in the runtime** (a different surface from the 94 that run *front-end*; do not conflate the two).

The non-claims in §3–§5 are exactly the complement of that surface. Full positive enumeration: [`COBOL-PARITY.md`](../COBOL-PARITY.md).

## 3. The compile axis — what we DO NOT claim

### 3a. Native code generation — a deliberate NON-GOAL (not a gap)

`GNURUST.FRONTEND.1` is an **interpreter over the ported `libcob` runtime**, not a native-code compiler. This is a settled architectural choice recorded as a non-claim, not an unfinished feature.

- No code generation, no C emission, no `.o` / `.s` / `.so` / standalone executable is ever produced.
- The behaviour a native compiler would produce is instead **reproduced by the interpreter and sweep-verified byte-for-byte** against `cobc -x`. The observable result matches; the mechanism is interpretation, by design.
- **Risk if mis-stated:** the false summary "gnucobol-rs is a COBOL compiler." It is not — it is a behaviour-faithful interpreter over a faithful runtime port.

Because there is no compiler, the following compiler-shaped surfaces are also explicit non-claims:

| Surface | Where handled | Guard | Why a non-claim | How it leaves |
|---|---|---|---|---|
| `.o`/`.s`/`.so`/executable emission | n/a — no codegen path exists | architectural | interpreter reproduces behaviour instead | never (non-goal) |
| `cobc` drop-in / build-profile auto-detection from bytes | host driver `cobrun.rs` | honest self-identification (not GnuCOBOL) | not a compiler replacement | `GNURUST.BUILD.PROFILE.1`, `GNURUST.LINEAGE.CORPUS.20M.*` (observed atlas only) |
| Compiler/optimization/codegen `>>` directives; `-std` codegen effects | `preprocess` (`frontend.rs:292`), `cobrun` arg parse | pass-through / no-op; observed-only | no codegen to direct | `GNURUST.DIRECTIVE.VARIANCE.ATLAS.1`, `GNURUST.DIALECT.RUNTIME.ATLAS.1` (observed atlas) |

### 3c. `cobc` diagnostic / warning / help TEXT — not byte-reproduced

We claim byte-identical **program stdout**, not byte-identical **compiler chrome.** gnucobol-rs does **not** reproduce, byte-for-byte: `cobc`'s warning text, error-diagnostic text, source-listing, or `--help`/usage output; nor its `-V` / `--version` / `-dumpversion` banner — `cobrun` honestly identifies as **the port**, not GnuCOBOL. This is a declared boundary, not a refusal to run: the program still executes; we simply make no claim that the *compiler's* textual surface matches.

### 3d. Localized (non-`C`/`C.UTF-8`) messages — not claimed

Runtime-message behaviour is reproduced only under the `C` / `C.UTF-8` baseline. `print_runtime_conf` forces `LC_NUMERIC` and `LC_CTYPE` to `"C"` (faithful to `libcob`; `cobrun.rs:40-84`). **Translated / localized `libcob` or `cobc` message catalogues** under other `LC_MESSAGES` locales are an explicit non-claim — byte-identity of messages under other locales is not asserted.

## 4. True oracle boundaries — non-claims because no oracle behaviour EXISTS

These are **not gaps and not latent tasks.** GnuCOBOL 3.2 itself does not run them, so there is no fixed oracle output to be faithful to. Refusing them *is* the correct, oracle-matching behaviour. Authority: [`COBOL-PARITY.md`](../COBOL-PARITY.md), [`reports/claim-ladder.json`](../reports/claim-ladder.json).

| Boundary surface | Where rejected | Guard | Why no oracle exists | How it leaves |
|---|---|---|---|---|
| **COMMUNICATION SECTION** verbs: SEND, RECEIVE, PURGE, ENABLE, DISABLE | `exec_stmt` | frontend.rs:3481 | GnuCOBOL 3.2 does not implement the COMMUNICATION SECTION | only if upstream GnuCOBOL implements it |
| **ACUCOBOL GUI** verbs: MODIFY, INQUIRE | `exec_stmt` | frontend.rs:3485 | absent from the GnuCOBOL 3.2 grammar; the oracle rejects them | only if admitted into the oracle grammar |
| **`ENTRY`** in a nested program | `exec_stmt` | frontend.rs:3490 | invalid in a nested program; requires separately-compiled units (outside the single-module model) | with multi-module linkage (itself a non-claim, §5) |
| **16 boundary intrinsics** (below) | `eval_intrinsic` / function resolve | 5270+/5673 | absent, inactive, or non-`libcob` substrate — no fixed oracle value exists | only if a fixed oracle value appears upstream |
| **USAGE NATIONAL (UTF-16)** | data-division parse | 640/641 | GnuCOBOL 3.2 declares it unfinished (`-Wunfinished`); explicit `USAGE NATIONAL` does not compile | only with upstream completion + an oracle |

**The 16 boundary intrinsics** (each a non-claim because the oracle yields no stable value — *not* implementation gaps):

- `cobc: "FUNCTION is not implemented"` → BOOLEAN-OF-INTEGER, CHAR-NATIONAL, DISPLAY-OF, EXCEPTION-FILE-N, EXCEPTION-LOCATION-N, INTEGER-OF-BOOLEAN, NATIONAL-OF, STANDARD-COMPARE.
- `cobc` rejects as unknown (`libcob`-internal helper, not a user function) → BINOP, LCL-TIME-FROM-SECS, MON-DECIMAL-POINT, MON-THOUSANDS-SEP, NUM-DECIMAL-POINT, NUM-THOUSANDS-SEP.
- Compiler-artifact / foreign-substrate boundaries → MODULE-PATH (compiled-binary path; the interpreter produces no binary), RANDOM (GMP internal Mersenne-Twister RNG; the port does not link `libgmp`, so no algorithm-identical stream oracle exists).

> The **94** intrinsics that *do* run front-end (ABS, MOD, NUMVAL, CURRENT-DATE, FORMATTED-DATETIME, PRESENT-VALUE, TRIM, the trig/log family, …) are **capabilities**, not boundaries, and are listed in `COBOL-PARITY.md`. They MUST NOT be read into the boundary set above.

## 6. How a surface leaves this registry

A surface departs only by becoming **executed, oracle-backed evidence** — never by quiet promotion or an implied "probably works." The path differs by row type:

1. **Fail-closed form (§3b) → sealed court.** Add a positive corpus program under `lab/corpus/frontend/` and make it byte-match both pinned oracles in `cobol_frontend_sweep.sh`. The surface graduates into a sealed court in `reports/claim-ladder.json`, the row is **deleted** here, and the surface is added to `COBOL-PARITY.md`. This is the path edited PICTURE (via `GNURUST.16`), DIVIDE (via `GNURUST.19`), COMP (via `GNURUST.14`), file/screen I/O, and 130+ other surfaces have already taken.
2. **Open data/runtime non-claim (§5) → sealed court.** Seal a dedicated court (the precedent is the `GNURUST.INDEX.1` synthetic-PIC seal and the planned `BINARY-*` `LENGTH OF` court). The row moves from "open" to the sealed list and is removed here.
3. **Declared non-goal / boundary (§3a, §3c, §3d) → receipted policy.** These do **not** "seal" — they are documented decisions with a receipt (e.g. native codegen as a recorded non-goal, diagnostic-text non-reproduction as a declared boundary, a `BINARY-* UNSIGNED` consume-and-ignore non-claim with a small-non-negative round-trip receipt). They leave only if the project's scope is explicitly changed and re-declared.
4. **True oracle boundary (§4) → only if the oracle changes.** A boundary leaves **only if GnuCOBOL itself implements the surface** with a stable, reproducible value — at which point it becomes a fail-closed *gap* eligible for a court, not a permanent boundary. Listing it as a future task would be inaccurate.

Until one of those happens, the surface **must fail closed** with a typed `RunError` at the cited site. The planned negative corpus (the `lab/corpus/frontend-reject/` sweep) is the instrument that turns each prose non-claim above into **executed** evidence that the refusal actually fires; once wired, this registry — its non-claim count, its corpus size, and its sealed-court list — is regenerated from the executed accept + reject sweeps and from `reports/negative-capabilities.json` + `reports/claim-ladder.json`, not from prose. **A row that has not earned a passing oracle receipt does not leave this list.**
