# TRUST.4 — generated forensic case files

> _Generated document (TRUST.4.DOCS). Machine authority: `reports/claim-ladder.json` + `reports/casefiles/`. Legacy source preserved losslessly under `research/legacyreports/docs/trust4-forensic-casefiles.md`._

> [!IMPORTANT]
> **Doctrine.** TRUST.4 makes every report a generated forensic case file: claims, non-claims, negative
> capabilities, evidence hashes, replay commands, and portable attestations are produced from court runs,
> while human documentation is only a rendered view of machine-verifiable evidence.

TRUST.2 made receipts generated; TRUST.3 made proof safe to interpret; **TRUST.4 makes every report
portable, attestable, and forensic.**

## Three layers per court

`reports/casefiles/<case_id>/` (generated by `lab/casefile/run.py` from the claim-ladder + TRUST.2
receipts — never hand-written):

| file | role |
|------|------|
| `casefile.json` | **evidence of record** — case id, kind, crate+version, oracle, results, positive/negative claims, byte domains, replay command, hash chain |
| `casefile.md` | generated human rendering (`DO NOT EDIT BY HAND`) |
| `sarif.json` | SARIF 2.1.0 — verdict + every non-claim as a portable finding |
| `intoto-statement.json` | in-toto v1 — materials (claim-ladder + receipt hashes) → product (casefile) |
| `dsse-envelope.json` | DSSE envelope around the in-toto statement (**unsigned** until a key is configured) |

The shared **negative-capability registry** is `reports/negative-capabilities.json` — every surface this
stack refuses to guess, with an ID, guard, and risk-if-guessed; casefiles reference these IDs.

## The gate (`lab/casefile/run.py check`, run by the doc-gate)

Fails if: a casefile's `.md`/`.sarif` ≠ regenerated (a manual edit), `casefile.json` ≠ regenerated from
the claim-ladder/receipt, **negative claims < positive claims** (negative capability is the trust
surface), a claim-ladder court has no casefile, or a casefile references a missing receipt.

## Report kinds

`court-casefile` (GNURUST) · `composition-casefile` (KOBOLD.DATA) · `operator-casefile`
(KOBOLD.OPERATOR/FILE) · and later `release-casefile`, `deployment-casefile`, `benchmark-casefile`.

## Signing

`dsse-envelope.json` is generated **unsigned** — the envelope shape is admitted now; cosign / minisign /
sigstore can sign it later without changing the casefile. TRUST.4 is not blocked on signing infrastructure.
