## 3. What "clean-room" can honestly mean here

- **Supported term:** the parser is an **independently written** COBOL front-end per the author's
  committed claim, developed against the ORACLE (behavioral differential), not against `cobc`
  source.
- **Not supported by the committed record:** the stricter legal/process term "clean-room" — which
  requires a demonstrable separation of the implementation team from the reference implementation
  and its documentation. The repository contains no record proving (or disproving) that separation.
- **Consequence:** documentation must qualify the term. Where the README/docs say "clean-room"
  about the parser, the accurate phrasing is "independently written (author's from-scratch claim;
  strict clean-room provenance not independently verifiable from the committed record)". The
  runtime is a derivative either way (previous document).

## 4. How to resolve the UNKNOWNs

- Add a `docs/methodology/parser-provenance.json` entry per phase: tooling, consulted documents,
  LLM usage (or explicit none), and review notes — committed at the time of writing.
- Keep the oracle-differential evidence model (it is the strongest available evidence).
- If the author can attest tooling/materials from memory, record it as an author attestation
  (with date), not as committed-process evidence.
